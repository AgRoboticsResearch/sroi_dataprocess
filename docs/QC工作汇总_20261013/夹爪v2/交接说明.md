## 1. 用户需求（原话归纳）

针对 `gripper_estimation_april_tag.py` 的夹爪动作恢复，用户提了 5 点：
1. **尖峰剔除**：少量数据有 1-2 帧孤立尖峰（2 帧仅见过一次）。特征：与左右
   两侧都差别巨大（归一化阈值 0.15 合适）、尖峰前 2-3 帧相互接近、后 2-3 帧
   相互接近、前后彼此也接近（=平坦处突发）。直接剔除。
2. **强光鲁棒性**：20 条专门强光环境的 episode（`120_onesb_supplementary/
   20260723_161913-png`），人眼看 tag 清楚但算法识别有问题。
3. **对称硬件约束**：RGB 相机对准钳口中心，左右 tag 关于画面中心对称（偏差
   几个像素无妨）。现在必须双 tag 都检出才算——应改为：单 tag 遮挡时用对称
   约束推算；双 tag 时交叉验证。
4. **平滑性/楼梯感**：怀疑快速钳口运动→拖影→丢检，旧逻辑取前一个有效值
   造成台阶。拖影应左右同时丢检，消失前后钳口距离不同→应做**线性插值**。
5. （补充消息）问题不只在强光 20 条：完整 1115 条里有少量尖峰；末端完全遮挡
   只能舍弃但单 tag 遮挡应可恢复；有 episode 肉眼正常但动作在 0.96-0.98 附近
   跳变（识别不正常）；整体希望动作尽量平滑。
   **旧的动作恢复图（episode 里的 gripper_distances.txt/jpg）不要删**，要和新
   方案对比。

## 3. 关键实测依据（本会话测得）

- **对称中心极稳**：20260709 三个 episode std 0.07-0.14px、最大偏 0.5px；
  但不同 rig 中心不同（20260709≈328.8，强光 161913≈324.3）→ 必须 per-run 估计，
  不能全局硬编码。sym tol 取 6px 很宽松。
- **预处理实验**（强光失败集全帧测试，左 tag ID0 检出数）：
  012: 原样 1/98 → CLAHE 96 → equalizeHist **98**；013: 0 → 98 → **100**；
  015: 0 → 68 → L67/**R80**。结论：equalizeHist 最强，链条保留两者。
- **强光根因**：012/013 是左 tag 丢失（右侧 ~90% 正常）→ 对称约束+预处理双保险；
  015 两个都丢（p5=35/p95=253 极端对比度）→ 靠 equalizeHist 恢复。
- **真实快速运动相邻有效帧跳变可达 67px**（145604/ep_030）→ 简单差分判尖峰会
  误杀，平坦上下文判据是必须的（单测验证斜坡/平台阶跃/3帧偏离均不删）。
- **历史尖峰在当前严格参数下不复现**：1019 条现有输出扫出 10 处尖峰（全部
  单帧，如 0.039→1.0→0.035），但用当前 config 参数重跑同样的 episode 尖峰
  消失（如 152317/ep_009 帧 1）——历史输出疑似旧参数（如 batch 默认 roi200/
  diag42±15）产生。**新方案的尖峰剔除在真实数据上的验证还没完成**（见 §5）。
- pupil_apriltags `nthreads=4` 在退出时段错误（结果有效），代码里用 nthreads=1。
- 帧率：全流程 nthreads=1 时约 10-15 帧/秒/episode。
